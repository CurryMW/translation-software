# 最终未打包扩展：安装、配置、清除、费用与已知限制

## 交付形态

这是个人使用的 Chrome Manifest V3 解压扩展，不是 Chrome Web Store 包。交付目录是构建生成的 `dist/`；不要把 APPID、密钥、真实网页内容或请求日志放进仓库、压缩包或聊天。

## 安装

1. 在仓库根目录运行 `npm run build`；需要先确认 `npm run verify` 的结果，且没有真实百度/第三方网站调用。
2. Chrome 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择仓库下的 `dist/`。
3. 打开扩展详情，确认没有 service worker 错误；工具栏固定扩展图标后，从 popup 打开设置页。
4. 安装时不授予所有网站权限。首次为某个 `http/https` 网站开启页面翻译时，Chrome 才请求该域名权限；拒绝即不读取、不注入、不发送正文。Chrome 内部页、浏览器内置 PDF、Canvas/图片文字等边界见根目录 [`KNOWN_LIMITATIONS.md`](../../KNOWN_LIMITATIONS.md)。

## 配置

1. 在设置页输入用户自己的百度通用文本翻译 APPID 与密钥，点击“保存凭据”。输入值只进入本机扩展存储，保存后不回显；浏览器端本地存储不是加密保险箱，不应复用高权限或长期主密钥。
2. 选择当前账户实际可用的百度套餐和本地月度字符预算。界面中的“本扩展估算”不是百度官方账单、账户总用量、免费额度或零费用承诺。
3. 先在 popup 为网站授权并开启翻译，再按每次切入确认决定是否提交新增任务。只发送当前安全可视文本块和百度接口所需字段，不发送整页、URL、标题、账号、相邻上下文、密钥或签名原串。

## 清除与撤销

当前实现的设置页按钮是“清除凭据”，它会移除百度 APPID/密钥及其配置状态；它**不是**“清除本地数据”完整实现的替代品。完整清除门槛仍在 #27 记录中保持 `pending`，因此不得把当前候选称为已满足彻底清除要求。

若需要在本机尽量清理：

1. 在 popup 关闭已开启的网站翻译；
2. 设置页点击“清除凭据”；
3. 在 `chrome://extensions` 的扩展详情中移除该解压扩展；
4. 在 Chrome 的网站访问权限设置中逐一撤销已授予域名权限。

Chrome 已授予的网站权限不由 `chrome.storage.local` 自动删除；移除扩展前后都应单独检查。待完整“清除本地数据”操作覆盖凭据、网站开关/目标语言、兼容性暂停、用量与诊断记录后，才能将该门槛改为 `pass`。

## 费用与真实百度提示

- 已提交给百度的请求可能无法撤销，关闭页面或取消等待任务不保证撤销费用。
- 本地预算只是扩展根据已提交源字符的估算；百度套餐、价格、免费额度、QPS、单次长度、语言方向和数据条款以用户当前账户与官方页面为准，不能从仓库文档推断。
- 真实百度 smoke 只允许设置页中的两次明确操作：固定无敏感文本，总源字符不超过 300；提交前展示字符数；不自动重试；失败仅显示脱敏错误类别。
- 普通页面自动化使用 Fake Adapter；百度适配器自动化只使用假凭据和注入的合成 transport 响应，真实 `dist` 双确认回归额外启用浏览器离线模式。自动化不得访问百度；这些测试通过不等于真实凭据、账户或费用已验证。普通页面只有用户人工烟囱通过后才切换到百度。

## 已知限制

已知安全边界集中在 [`KNOWN_LIMITATIONS.md`](../../KNOWN_LIMITATIONS.md) 和 `static/KNOWN_LIMITATIONS.md`。除既定平台边界外，以下 #27 交付门槛在当前记录中仍未闭合：

- #26 的 X、英文 Wikipedia、GitHub Issue/Discussion、Hacker News 四站人工核心路径；
- 当前套餐/计费/QPS/语言方向的持续用户核对与官方账单核对（真实百度 smoke 已由用户完成）；
- 30 个固定样本逐样本质量与完整性结果；
- X 十分钟连续滚动的无重复/无失控请求/内存体感记录；
- 完整“清除本地数据”行为及其候选构建验收。

这些项目必须写成 `pending` 或 `blocked`，不能用“不支持”掩盖普通缺陷，也不能把本地 fixture、Fake Adapter 或 #13 的局部记录扩大成最终 MVP 通过。
