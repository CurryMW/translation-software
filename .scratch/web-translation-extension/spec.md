# Chrome 网页翻译扩展 MVP 规格

Status: ready-for-agent

## Problem Statement

用户在 Chrome 中阅读 X 信息流、文章、Issue、评论等外语网页时，希望直接在每个可阅读文本内容块下面看到目标语言译文，而不是切换到独立翻译页面、复制粘贴文本，或用整页翻译替换原文。现有页面结构复杂且持续变化：导航、按钮、链接、代码、账号信息和编辑区不能被误当成正文；动态内容、标签页切换和乱序网络响应也可能造成重复翻译、错位译文、隐私泄露或不可控的 API 调用费用。

本项目当前只有规划、研究和一次性交互原型，没有正式扩展源码。需要从零实现一个供个人通过 Chrome“加载已解压的扩展程序”使用的 Manifest V3 MVP，并在内容覆盖、页面安全、凭据隐私、百度调用成本和真实网站兼容性之间建立明确、可验证的边界。

## Solution

构建一个 TypeScript + React 的 Chrome Manifest V3 扩展。用户在设置页保存自己的百度通用文本翻译 APPID 与密钥，为某个网站首次开启翻译时按域名授予权限，并为该网站选择目标语言。扩展仅识别当前实际可视区域中的文本内容块，保留原文，在对应内容块下方以紧凑双语样式呈现译文；页面滚动、异步新增或原文变化时增量处理。

React 负责 popup、设置页和网页内译文/提示界面；内容发现、翻译会话、任务队列、语言规则、兼容性和翻译服务适配器保持为纯 TypeScript。页面只把经用户确认且通过内容安全规则的当前文本内容块发送给 service worker。只有 service worker 可以读取凭据、生成百度签名并发起请求。扩展不持久保存原文、译文或翻译历史，并通过本地字符预算、套餐感知队列、有限重试、过期结果校验和兼容性暂停控制费用与风险。

首版只实现百度通用文本翻译，但保留最小翻译服务适配器接缝。自动化默认使用确定性 Fake Adapter，真实百度只在安全门通过后由用户从设置页显式执行少量烟囱测试。

## User Stories

1. 作为个人用户，我希望通过 Chrome 的“加载已解压的扩展程序”安装扩展，以便在不上架商店的情况下使用 MVP。
2. 作为个人用户，我希望从工具栏打开清晰的 popup，以便查看当前网站的翻译状态。
3. 作为个人用户，我希望安装扩展时不立即授予所有网站访问权限，以便控制扩展能读取哪些网站。
4. 作为个人用户，我希望首次为某个网站开启翻译时再授权该网站域名，以便权限申请与我的明确操作相对应。
5. 作为个人用户，我希望拒绝网站权限后页面保持原状且不发送正文，以便拒绝不会产生副作用。
6. 作为个人用户，我希望在 Chrome 内部页面等不支持的页面看到明确说明，以便知道问题不是百度凭据失效。
7. 作为个人用户，我希望在设置页填写自己的百度 APPID 和密钥，以便扩展使用我的翻译账户。
8. 作为个人用户，我希望保存后的密钥不被明文回显，以便旁观者无法从设置页读取它。
9. 作为个人用户，我希望能够测试、替换和清除百度凭据，以便维护账户配置而不编辑源代码。
10. 作为个人用户，我希望设置页明确说明本机扩展存储不是加密保险箱，以便理解个人 MVP 的安全边界。
11. 作为个人用户，我希望凭据不出现在网页、content script、日志、测试报告或网络请求的密钥字段中，以便降低泄露风险。
12. 作为个人用户，我希望清除本地数据时同时删除凭据、网站设置和诊断记录，以便彻底清理扩展数据。
13. 作为个人用户，我希望扩展说明网站权限可能需要在 Chrome 权限界面单独撤销，以便正确完成权限清理。
14. 作为个人用户，我希望为当前网站开启或关闭页面翻译开关，以便按网站控制自动翻译。
15. 作为个人用户，我希望页面翻译开关按域名记忆，以便同一网站下次仍采用我的选择。
16. 作为个人用户，我希望新网站默认把简体中文作为目标语言，以便主要阅读场景无需重复设置。
17. 作为个人用户，我希望每个网站分别记忆目标语言，以便不同网站可以使用不同译文语言。
18. 作为个人用户，我希望切换目标语言后仅重译当前标签页的可视内容，以便及时更新而不触发其他标签页费用。
19. 作为个人用户，我希望扩展自动识别源语言，以便通常不需要手工选择。
20. 作为个人用户，我希望识别错误时能够为单个文本内容块指定源语言并重试，以便纠正个别识别问题。
21. 作为个人用户，我希望已经是目标语言的内容被跳过，以便避免无意义调用。
22. 作为个人用户，我希望语言无法可靠判断时由我手动决定是否翻译，以便扩展不会反复自动请求。
23. 作为个人用户，我希望正常的短外语短语仍可翻译，以便短内容不会仅因字符少而遗漏。
24. 作为个人用户，我希望纯数字、纯标点和纯 emoji 自动跳过，以便不浪费额度。
25. 作为个人用户，我希望扩展按段落、帖子、评论、列表项、图片说明或引用等文本内容块翻译，以便译文保持完整语义。
26. 作为个人用户，我希望扩展不按屏幕换行逐行翻译，以便窗口宽度变化不会改变翻译单位。
27. 作为个人用户，我希望父子内容重叠时只翻译最小且完整的文本内容块，以便不会出现重复译文。
28. 作为个人用户，我希望导航、工具栏、按钮、菜单、页脚、广告、表单和可编辑区域不被翻译，以便网站交互保持正常且输入内容不外发。
29. 作为个人用户，我希望所有链接文字被排除，以便链接标题和用户名等内容不会被扩展提交。
30. 作为个人用户，我希望链接排除后不再构成完整语义的内容块整体跳过，以便不产生残缺、误导性的译文。
31. 作为个人用户，我希望隐藏、折叠、`aria-hidden` 或 `display:none` 内容不被提交，以便扩展只处理当前可读内容。
32. 作为个人用户，我希望扩展只翻译当前实际可视区域，以便不为屏外内容预先消耗额度。
33. 作为个人用户，我希望内容滚入视口后才开始排队翻译，以便调用与我的阅读行为一致。
34. 作为个人用户，我希望尚未发送就滑出视口的任务取消排队，以便不翻译已经离开的内容。
35. 作为个人用户，我希望译文显示在对应原文下方、原网站操作区之前，以便阅读顺序自然。
36. 作为个人用户，我希望原文始终保留，以便可以对照翻译结果。
37. 作为个人用户，我希望译文默认展开，以便无需逐条点击。
38. 作为个人用户，我希望能够收起或重新展开单个译文，以便控制页面密度而不重新调用 API。
39. 作为个人用户，我希望翻译请求开始后立即看到加载状态，以便知道扩展正在工作。
40. 作为个人用户，我希望单个文本内容块失败时原文仍可阅读并提供单块重试，以便局部故障不影响整页。
41. 作为个人用户，我希望供应商级故障只显示一条顶部提示并暂停整页队列，以便页面不会堆满重复错误。
42. 作为个人用户，我希望长译文自然撑高页面并保留段落，以便内容不会覆盖原文或变成难读的一团。
43. 作为个人用户，我希望译文界面适应浅色和深色网页，以便保持清晰对比度。
44. 作为键盘用户，我希望翻译、收起、展开、确认和重试操作具有可见焦点及可访问名称，以便无需鼠标操作。
45. 作为网页用户，我希望扩展样式不修改宿主网站的全局样式，以便页面原有布局和组件不受污染。
46. 作为个人用户，我希望异步加载的新帖子或评论在进入可视区域后自动翻译，以便支持 X 等动态信息流。
47. 作为个人用户，我希望展开长帖或原文变化后旧译文立即失效，待文字稳定后重新翻译，以便译文不会对应旧内容。
48. 作为个人用户，我希望乱序返回的旧请求不会覆盖新内容，以便快速滚动和编辑不会造成错位译文。
49. 作为个人用户，我希望每个文本内容块最多只有一个译文容器，以便 MutationObserver 和重复扫描不会产生重复 UI。
50. 作为个人用户，我希望刷新或导航后页面内缓存清空，以便扩展不会把其他页面的译文错误复用。
51. 作为个人用户，我希望同一页面内相同原文、源/目标语言和供应商的结果可以复用，以便减少重复请求。
52. 作为个人用户，我希望切入已开启翻译的网站标签页时每次先询问是否翻译，以便本次停留仍由我授权新增调用。
53. 作为个人用户，我希望关闭切入提示不等于同意，以便扩展不会因为我忽略提示而发送正文。
54. 作为个人用户，我希望选择“暂不翻译”后保留已有译文但停止新增请求，以便现有阅读上下文不丢失。
55. 作为个人用户，我希望后台标签页不提交新的自动翻译任务，以便控制费用和后台活动。
56. 作为个人用户，我希望关闭网站翻译开关后清除等待任务和译文界面但保留原文，以便页面恢复原状。
57. 作为个人用户，我希望扩展明确说明已提交的第三方请求可能无法撤销，以便理解关闭功能不一定取消既有费用。
58. 作为个人用户，我希望普通 DOM、开放 Shadow DOM 和已获权限 iframe 尽力得到支持，以便覆盖更多现代网页。
59. 作为个人用户，我希望关闭 Shadow DOM、Canvas/图片文字、浏览器 PDF 和无权限跨域 iframe 被明确标为不支持，以便不会误以为插件失效。
60. 作为个人用户，我希望长文本按段落和句子安全拆分并按原顺序合并，以便不因接口长度限制截断或乱序。
61. 作为个人用户，我希望无法安全拆分的长文本明确失败而不是静默截断，以便不会漏译内容。
62. 作为个人用户，我希望网络、超时和临时服务异常最多自动重试两次，以便提高成功率但不产生无限调用。
63. 作为个人用户，我希望限流请求进入受控队列，以便不会同时重试并继续触发限流。
64. 作为个人用户，我希望鉴权、签名、余额、配额、不支持语言和无效参数错误不自动重试，以便不浪费额度。
65. 作为个人用户，我希望能够选择百度套餐并设置可编辑的本地月度字符预算，以便扩展达到估算上限后暂停自动翻译。
66. 作为个人用户，我希望界面把本地字符预算明确标为“本扩展估算”，以便不会误认为它是百度官方账单。
67. 作为个人用户，我希望真实百度测试使用预置无敏感文本且一次不超过300个源字符，以便验证配置时控制费用。
68. 作为个人用户，我希望真实百度烟囱测试在显示字符数并二次确认后才执行，而且不自动重试，以便不会误触发额外调用。
69. 作为个人用户，我希望扩展不持久保存原文、译文、请求体、响应体或翻译历史，以便减少本机隐私数据。
70. 作为个人用户，我希望诊断只记录脱敏错误类别、服务错误码和时间，以便排查问题时不暴露阅读内容。
71. 作为个人用户，我希望无法确认内容安全时扩展宁可跳过，以便隐私和网页安全优先于覆盖率。
72. 作为个人用户，我希望扩展导致布局、按钮或滚动异常时立即移除自己的 UI 并暂停本页，以便宿主网页恢复可用。
73. 作为个人用户，我希望已知会泄露内容、破坏页面或造成费用失控的网站被兼容性暂停，以便不会跨会话重复遇到高风险问题。
74. 作为个人用户，我希望兼容性暂停在修复通过前不能强制绕过，以便安全限制不会形同虚设。
75. 作为个人用户，我希望安全降级只影响当前内容块、页面或网站，以便其他网站仍可正常使用扩展。
76. 作为个人用户，我希望遇到已知限制时只看到简短、可执行的提示，以便不用理解开发术语。
77. 作为维护者，我希望通用内容识别问题优先做通用修复，以便避免维护大量易失效的网站选择器。
78. 作为维护者，我希望只有核心或高影响场景无法安全通用处理时才创建站点特例，以便控制长期维护成本。
79. 作为维护者，我希望每个站点特例独立注册、可关闭且有安全回退，以便网站改版时不会污染通用扫描器。
80. 作为维护者，我希望每个站点特例记录适用域名、原因、触发条件、合成夹具和复查时机，以便后续判断是否继续保留。
81. 作为维护者，我希望已知不支持与明确延期记录在随扩展交付的限制清单中，以便真实能力边界可以审计。
82. 作为维护者，我希望普通缺陷不能通过标记“不支持”绕过，以便放行门槛不会被稀释。
83. 作为维护者，我希望翻译服务通过统一适配器接入，以便将来可以增加 DeepL 等供应商而不改动页面流程。
84. 作为维护者，我希望首版设置页只展示实际实现的百度翻译，以便不暴露不可用的供应商选项。
85. 作为开发者，我希望在接触真实百度前使用确定性 Fake Adapter，以便零费用复现成功、超时、限流、鉴权失败、配额、乱序和取消。
86. 作为开发者，我希望真实 APPID 和密钥永远不进入仓库、聊天、命令输出或快照，以便开发流程不复制凭据。
87. 作为开发者，我希望每个行为切片先有失败测试再写最小实现，以便测试验证真实需求而不是事后贴合代码。
88. 作为开发者，我希望通过一个默认不访问真实百度和第三方网站的统一验证入口执行全部自动检查，以便每个阶段都能稳定回归。
89. 作为测试者，我希望本地夹具分别覆盖静态内容、排除项、主题、动态信息流、原文更新、乱序响应、Shadow DOM 和 iframe，以便失败能够准确定位。
90. 作为测试者，我希望真实网站检查表不保存账号、正文、译文、完整 URL 或真实页面截图，以便验收证据本身不会产生隐私风险。
91. 作为测试者，我希望 X、Wikipedia、GitHub 和 Hacker News 各检查至少5个可翻译块及主要排除区域，以便通用性结论有一致标准。
92. 作为测试者，我希望30个固定跨类型样本的内容对应、顺序、目标语言、无遗漏/重复/截断达到100%，以便验证扩展集成完整性。
93. 作为测试者，我希望至少90%的固定样本能够正确理解主旨且无反向含义，以便发现明显不可用的翻译结果。
94. 作为测试者，我希望供应商措辞质量与扩展数据损坏分别记录，以便问题归因准确。
95. 作为测试者，我希望确认后200毫秒内看到加载状态，以便交互有即时反馈。
96. 作为测试者，我希望单次可视区域扫描 P95 不超过100毫秒，以便扩展不会明显阻塞页面。
97. 作为测试者，我希望正常网络下首条译文中位数不超过2.5秒、P95不超过6秒，以便端到端体验达到个人 MVP 门槛。
98. 作为测试者，我希望在 X 连续滚动10分钟时没有重复译文、失控请求或明显卡顿，以便核心动态场景可靠。
99. 作为测试者，我希望扩展带来的内存增量目标不超过50MB，以便长时间浏览不会明显增加资源压力。
100. 作为测试者，我希望测试失败先分类为代码回归、测试缺陷或外部网站变化，而不是自动重试到通过，以便不稳定问题不会被隐藏。

## Implementation Decisions

### 平台与模块

- 使用 Chrome Extension Manifest V3；`minimum_chrome_version` 以120作为经 API 可用性核对的设计兼容下限。只有实际人工运行过的当前 Chrome Stable 可以标记为已验证，不声称所有 Chrome 120+ 版本都已实测。
- 使用 TypeScript + React 和受控的最小前端构建链，生成可通过 Chrome 加载的 `dist` 产物。
- React 仅负责 popup、设置页、页内译文、切入确认和错误提示。内容发现、翻译会话、消息、调度、兼容性、存储端口和供应商适配器保持为纯 TypeScript。
- 网页内多个译文位置由统一 React 渲染协调层管理，可通过受控挂载点或 portal 呈现；不得为每个文本内容块创建互不协调的完整应用实例。
- 模块依赖方向从 React UI 指向纯 TypeScript 接口；核心模块不得依赖 React。
- 首版实现内容发现模块、翻译会话模块、运行时消息模块、设置与权限模块、凭据存储模块、任务调度模块、翻译服务适配器模块、百度传输适配器、兼容性注册模块、脱敏诊断模块和 React UI 模块。

### 权限、设置与凭据

- 安装时不得申请所有网站的主机权限。用户首次为网站开启翻译时，从明确的用户操作申请对应 `http/https` 域名权限；拒绝权限时不注入、不扫描、不发送正文。
- 百度翻译主机权限与网页读取权限分离，并保持为完成供应商请求所需的最小范围。
- 网站设置以域名为键保存页面翻译开关和网站目标语言；不同网站相互独立。
- 百度 APPID 与密钥保存在 `chrome.storage.local`，不写入源代码、manifest、构建变量或版本控制文件。
- service worker 初始化时把 `chrome.storage.local` 访问级别限制为 `TRUSTED_CONTEXTS`。这只排除 content script，并不形成单脚本保险箱；代码结构还必须保证 popup、设置页和其他扩展页面没有读取或回显密钥的路径。
- 设置页通过类型化消息向 service worker 提交保存、测试、替换和清除操作。保存后只显示已配置状态，不回传密钥原文。
- “清除本地数据”删除凭据、网站开关/目标语言、兼容性暂停和诊断记录；界面说明 Chrome 已授予的网站权限可能还需额外撤销。

### 内容发现与语言规则

- 翻译单位是文本内容块，不是视觉行、任意文本节点或整个页面。
- 默认候选包括独立标题、正文段落、列表项、帖子、评论、图片说明和引用。导航、工具栏、按钮、菜单、页脚、广告、代码、表单、可编辑区域及扩展自己的 DOM 必须排除。
- 所有链接文字一律排除，包括完全由链接构成的新闻或帖子标题。移除链接后为空或不再构成完整独立语义的候选块整体跳过。
- 隐藏、折叠、`aria-hidden`、不可见样式和当前视口之外的内容不得发起自动翻译。
- 父子候选重叠时选择最小且完整的语义块。每个内容块在当前页面生命周期中以 DOM 节点引用和规范化原文哈希识别。
- 纯数字、纯标点和纯 emoji 跳过；正常外语短语不设置简单字符数下限。
- 混合语言候选在非目标语言内容约占30%或以上时才自动提交。该值是待固定语料校准的启发式规则，不能用拉丁字母数量代替语言识别。
- 源语言默认自动识别；无法可靠判断时显示手动翻译入口，不自动循环请求。用户可以为单个块选择手动源语言后重试。
- 已确认源语言与目标语言相同时跳过。
- 默认目标语言是简体中文；目标语言按网站保存。界面只展示百度当前账户与已验证适配器实际支持的语言方向。
- 用户切换网站目标语言时，当前标签页撤销旧翻译会话、移除旧译文并重译当前可视内容；其他标签页不批量重译。

### 翻译会话与动态页面

- 页面翻译开关是长期网站设置；切入翻译确认是每次进入已开启网站标签页时对本次停留新增调用的授权，两者不能合并。
- 每次切入已开启翻译的网站标签页时，在该页面内显示非阻塞确认。确认前不提交新增任务；关闭提示不视为同意。
- 选择“暂不翻译”保留已有译文但停止新增任务；下次切入仍询问。未开启翻译的网站不显示切入确认。
- 后台标签页不提交新的自动请求。网站开关关闭时取消等待任务并移除扩展 UI，保留宿主原文。
- 使用局部增量观察处理滚动、异步 DOM、SPA 导航、开放 Shadow DOM 和获准 iframe；任务发出前必须再次确认节点仍可见、页面会话仍获授权。
- 文字变化时立即使旧译文失效，等待短暂稳定后仅重新处理受影响且可视的文本内容块，避免流式变化造成连续调用。
- 翻译结果写回前校验页面、节点、规范化原文、源/目标语言和供应商版本。任何版本不匹配的结果丢弃，不覆盖新内容。
- 每个文本内容块最多一个扩展译文容器；重复观察、React 重渲染和供应商乱序返回不得产生重复容器。
- 页面内可按规范化原文、源/目标语言和供应商复用成功结果；失败结果不复用。刷新、导航或浏览器重启后清空，不持久化缓存。

### 呈现与交互

- 采用已确认的 A「紧凑双语」方案：保留原文，在对应文本内容块下方、原站操作区之前插入译文。
- 译文默认展开，显示轻量语言标签和收起操作；收起只改变展示状态，不产生新请求。
- 加载、成功、块级失败、手动源语言和单块重试均通过 React 组件呈现。
- 凭据无效、配额耗尽、供应商关闭等页面级故障暂停队列，并合并成单条顶部提示，不为每个块重复报错。
- 长译文自然撑高布局并保留段落，不覆盖原文。
- 所有页面内样式必须限定在扩展自己的挂载范围，不使用会影响宿主页面的全局 reset、标签选择器或无前缀变量。
- popup、设置页和页内 UI 支持浅色/深色背景、键盘操作、可见焦点、可访问名称和合理的展开语义。

### 翻译服务与成本控制

- 首发翻译服务是百度通用文本翻译。个人认证可用时优先个人高级版；标准版只作为 QPS 1 的低并发验证路径。实施时以目标账户显示的当前套餐、配额、QPS、语言方向和单次长度为事实来源。
- 建立最小翻译服务适配器接口，统一接收原文、源语言、目标语言和请求上下文，返回成功结果或归一化错误。首版只注册百度与测试 Fake，不在设置页展示 DeepL。
- 百度签名及网络请求只能在 service worker 中执行。签名按百度通用翻译规则组合 APPID、原文、随机 salt 和密钥，并生成32位小写 MD5；MD5 实现必须随扩展本地打包并用独立固定向量验证，不加载远程代码。
- 百度请求使用 POST，只发送接口必需的 `q`、`from`、`to`、`appid`、`salt`、`sign`。密钥本身和签名原串不发送；页面 URL、标题、账号名、相邻上下文和整页内容不发送。
- 长文本先按段落、再按句子拆分至当前套餐安全长度内，保持顺序合并。无法安全拆分的单段返回明确失败，不截断、不静默遗漏。
- 队列并发和发送速率由用户所选百度套餐的限制决定；标准版按 QPS 1 串行。限流进入队列等待，不允许所有文本块同时重试。
- 网络、超时和临时服务异常最多自动重试两次并逐次增加等待；鉴权/签名、余额/配额、不支持语言、内容风险和无效参数不自动重试。
- 本地字符预算按扩展实际提交的源字符累计，用户选择套餐时可用当前官方免费字符数初始化，并允许修改。达到预算后暂停自动翻译。
- 本地预算始终标注为本扩展估算，不代表百度账户总用量、其他客户端调用或零费用承诺。
- 已提交给百度的请求不能承诺撤销处理或费用；取消操作只阻止等待任务和过期结果写回。

### 隐私、诊断与兼容性

- 不持久保存原文、译文、请求体、响应体或翻译历史。
- 诊断只保存不含正文的错误类别、百度错误码和时间；不记录完整 URL、密钥、签名原串或认证信息。
- 真实服务安全门包括凭据隔离、最小化请求、字符预算、错误分类、超时/重试和日志脱敏。全部通过前只能使用 Fake Adapter。
- 无法确认内容安全时采用安全降级：跳过该块，不发送请求。整页无法安全识别时暂停本页新增翻译并显示非阻塞提示。
- 扩展导致布局、按钮、滚动等宿主功能异常时，立即移除当前页扩展 UI、取消等待任务并暂停页面会话。
- 稳定触发隐私、页面破坏或费用风险的域名进入兼容性暂停，跨会话阻止新增请求；修复通过回归前用户不能绕过。
- 兼容性处置顺序固定为风险隔离、通用修复、必要站点特例、安全延期。修复时间不改变严重度。
- 问题可由通用夹具复现或出现在多个结构无关网站时，按通用缺陷修复；不得用站点选择器掩盖通用算法问题。
- 站点特例仅在问题稳定复现、场景核心或影响显著、通用修复会伤害其他页面且存在可靠语义锚点时使用。
- 站点特例独立注册并记录域名、触发条件、原因、合成夹具、安全回退和复查时机。失效时只有通用安全检查独立通过才回到通用规则，否则跳过。
- 明确延期必须同时满足：无隐私/凭据/费用风险、不破坏页面、不影响四个必测站、不是通用缺陷、可安全降级，并已记录复现条件、影响和替代办法。
- 随扩展交付已知限制清单。运行时只在命中相关情况时显示简短可执行提示。
- 关闭 Shadow DOM、Canvas/图片文字、浏览器内置 PDF、Chrome 内部页和无权限跨域 iframe 是已知不支持边界。

### 分阶段交付

- 阶段一交付可加载的 Manifest V3 骨架、安全存储、权限、React popup/设置页、content script、service worker 和类型化消息；仅用假凭据，不发真实请求。
- 阶段二交付静态可视文本内容块发现、Fake 翻译和紧凑双语 React 呈现闭环。
- 阶段三交付语言策略、任务队列、长文本、预算、页面内复用、错误分类与失败 UI，仍只使用 Fake。
- 阶段四交付动态页面生命周期、滚动可见性、文字稳定、标签页切入确认、后台暂停、取消和过期结果保护。
- 阶段五在真实服务安全门通过后交付百度适配器，并由用户在设置页输入凭据完成低额度烟囱测试。
- 阶段六完成本地夹具、四个真实网站、固定语料、性能、隐私和兼容性总验收，生成最终可加载产物与使用说明。
- 六阶段原则上顺序推进。某阶段失败时，不进入依赖它的后续阶段；只允许修复当前阶段或进行无依赖准备工作。
- 每个阶段必须留下可加载产物、自动测试结果和对应人工检查证据。

## Testing Decisions

### 测试原则与行为接缝

- 好测试只验证调用者或用户可观察的行为，不测试私有函数、内部调用次数、内部队列数组、React 组件实例或组件树。只要公开行为不变，重构不应导致测试破裂。
- 使用用户已经确认的五个行为接缝：页面内容发现、翻译会话状态、翻译供应商适配器、Chrome 扩展运行链路和用户可见 React UI。
- 页面内容发现接缝以受控页面、视口与用户授权作为输入，观察产生的文本内容块或安全跳过结果。
- 翻译会话接缝以用户动作、页面事件、时间与供应商结果作为输入，观察任务状态、可见 UI 状态、提交/取消和过期结果行为。
- 供应商适配器接缝以统一翻译请求作为输入，观察统一成功结果或归一化错误；只在这个外部系统接缝使用 Fake。
- Chrome 扩展运行链路接缝从用户启用网站开始，观察权限、存储、消息、service worker、content script 和页面渲染的完整行为。
- React UI 接缝通过角色、标签、可见文本、焦点和用户操作观察，不通过实现属性或测试专用组件接口观察。
- 每个行为按红—绿纵向循环推进：先写一个在已确认接缝上失败的测试，再写最小实现使其通过，然后进入下一行为。不要先批量编写想象中的测试库。

### 自动化测试层级

- 使用 Vitest/Node 测试纯 TypeScript：内容规则、规范化/哈希、语言判断、会话状态机、队列、重试/退避、预算、分段/合并、错误映射、复用和过期结果。
- 使用 Vitest + React Testing Library + jsdom 测试 popup、设置页、译文、切入确认和错误提示的可见状态、校验、保存/清除、收起/展开、重试、焦点和键盘操作。Chrome 能力通过注入的最小端口模拟。
- 首版不引入 Vitest Browser Mode；jsdom 不能证明真实布局、视口、滚动、扩展权限或 service worker 行为。
- 使用 Playwright 的隔离临时 persistent context 和随附 Chromium 加载实际 `dist`，动态取得扩展 ID，测试 manifest、扩展页、content script、service worker、消息、存储、权限、动态 DOM、可视区域、开放 Shadow DOM、获准 iframe 和 worker 休眠恢复。
- 不复用用户日常 Chrome profile，不硬编码开发机扩展 ID，不用打开源码页面代替加载扩展产物。

### 固定资产

- 建立场景索引和多个聚焦本地页面：静态文章与排除项、浅/深主题、动态信息流、原文改写与乱序响应、开放 Shadow DOM、同源/跨域 iframe 权限边界。不保存真实网站 HTML。
- Fake Adapter 可以按固定脚本返回成功、慢响应、超时、限流、鉴权失败、余额/配额、乱序和取消；它不替代项目内部状态或队列模块。
- 百度传输契约用固定假凭据和独立人工写定预期验证 POST 字段、签名向量与错误映射；测试不得用被测实现重新计算预期，也不得包含真实密钥。
- 固定30个质量与集成样本：18个英文正文/帖子/评论、4个中英混合块、4个英文长文本/换行/特殊字符块、2个日语块、1个韩语块、1个西班牙语块。
- 排除语料独立覆盖链接、导航、按钮、菜单、代码、表单、编辑区、隐藏内容、纯数字、纯标点和纯 emoji，并断言没有翻译任务。
- 局部截图基线只覆盖本地 popup、设置页、页内译文与提示的关键状态、浅/深色和典型长文本；不对真实网站做整页截图。基线更新必须人工审阅。

### 自动放行与测试证据

- 提供统一的本地 `verify` 入口，依次执行类型检查、构建、Vitest 纯逻辑/React 测试和本地 Playwright 扩展 E2E。
- `verify` 默认零真实百度调用、零第三方网站依赖，不得因为环境中存在真实凭据就改变行为。
- 所有关键行为矩阵必须100%通过；代码覆盖率只作为发现盲区的参考，不以全局百分比替代行为门槛。
- 自动记录本地动态夹具的扫描耗时、请求数、队列深度和 DOM 插入数，计算中位数与 P95，并验证静止后无持续扫描或请求。
- 测试失败默认不自动重试到通过。先保存脱敏错误与环境，再分类为代码回归、测试缺陷或外部变化；核心本地测试不得跳过或隔离后放行。
- 自动证据只保存测试名称、通过/失败、耗时、计数、脱敏错误及浏览器/扩展版本；截图只允许来自固定本地夹具。
- 当前仓库没有既有正式源码或测试，因此不存在可复用的代码测试先例；已有一次性静态原型只作为 A「紧凑双语」视觉意图参考，不作为生产实现或测试结构先例。

### 人工验收

- 在当前正式版 Chrome 中加载与自动测试相同的 `dist`，检查 manifest/service worker 无错误、工具栏 popup、设置页、权限允许/拒绝/撤销、键盘交互、主题、字体缩放和长文本布局。
- X、英文 Wikipedia、GitHub Issue/Discussion 和 Hacker News 各检查至少5个应翻译文本内容块及主要排除区域，并验证授权、切入确认、加载/成功/失败、滚动新增、原文变化、无重复、关闭停止和页面不被破坏。四个网站任一核心路径失败都阻断 MVP。
- 对30个固定样本要求内容对应、顺序、目标语言、无遗漏/重复/截断等集成完整性100%；至少90%能够正确理解主旨且没有反向含义。供应商措辞问题与扩展数据损坏分开记录。
- 确认后200ms内显示加载状态；单次可视区域扫描 P95 不超过100ms；正常网络下首条译文中位数不超过2.5秒、P95不超过6秒。外部服务变慢必须表现为明确等待或失败状态。
- 在 X 连续滚动10分钟，要求无明显卡顿、重复译文或失控请求；页面静止后无持续扫描/请求；扩展内存增量目标不超过50MB。
- 人工检查表只记录日期、Chrome/扩展版本、网站类型、权限状态、通过项、数量、脱敏错误和备注，不保存账号、正文、译文、完整 URL 或真实网站截图。
- 真实百度烟囱测试只在安全门通过后由用户从设置页显式触发，使用预置无敏感文本，总源字符不超过300；提交前显示字符数并二次确认，不自动重试。

### 兼容性回归

- 通用缺陷必须加入最小本地夹具和失败测试，运行完整 `verify` 并人工复测四个核心网站。
- 站点特例必须加入不包含真实正文的合成夹具，运行完整 `verify`，人工复测目标站和至少一个结构无关网站，并验证特例失效时安全回退。
- 隐私或费用修复必须重跑完整真实服务安全门；外观修复运行相关 React 行为、局部截图和目标页面检查。
- 问题只有在修复前有复现证据、修复后检查通过且没有更高严重度回归时才能关闭。
- 每个 MVP 候选版本复查明确延期与站点特例；Chrome 主版本升级、目标站明显改版、通用扫描器变化或适配器测试失败时立即复查相关项。

## Out of Scope

- Chrome Web Store 上架、商店审核、自动更新和公开分发。
- 账号体系、团队协作、跨设备同步、订阅计费及开发者代管用户凭据。
- 自建后端代理；当前凭据方案仅用于个人解压加载版本。未来公开版本需要把签名和供应商请求迁移到后端或重新评估 BYOK 风险。
- 同时实现 DeepL、Microsoft Translator、百度大模型翻译或其他供应商；它们只保留为未来适配器候选。
- 桌面客户端、移动客户端和其他浏览器的正式支持。
- 本地大模型、离线翻译、OCR、图片文字翻译、Canvas 文字翻译和语音翻译。
- Chrome 内置 PDF 阅读器、Chrome 内部页面、关闭 Shadow DOM 和未获权限的跨域 iframe。
- 翻译搜索框、按钮、菜单、用户名、链接文字、代码、表单、编辑器或其他网站交互 UI。
- 预先为大量网站维护专用选择器；只有真实兼容性证据满足条件时才增加站点特例。
- 云端遥测、自动上传日志、保存浏览历史、翻译历史、真实网站 HTML 或真实网站截图。
- 在初始本地仓库阶段建立云端 CI；先提供可复用的本地验证命令，远程托管确定后再接入。
- 声称所有 Chrome 120+ 版本已经实际测试，或保证百度翻译质量、可用性、免费额度和永不产生费用。

## Further Notes

- 实现必须按六个可运行阶段推进：安全骨架、静态 Fake 闭环、任务编排、动态生命周期、百度真实适配器、真实网站加固与总验收。
- 真实 APPID 与密钥在第五阶段之前不需要，也不应由开发代理索取。第五阶段由用户在扩展设置页自行输入。
- A「紧凑双语」原型只用于确认呈现方向；其整列表重建方式不是生产实现方案。
- 百度套餐、价格、免费额度、QPS、单次长度、语言方向和数据条款属于动态事实；第五阶段必须以用户实际账户和当时官方资料重新核对。
- 当前百度研究建议个人认证可用时首选通用文本翻译高级版，标准版只用于 QPS 1 的低并发验证；百度大模型接口留作后续质量对照。
- DeepL API Key 是否免费取决于绑定套餐而非 Key 本身；该事实不改变首版只接百度的范围。
- 已知限制应随最终扩展交付并在运行时按场景显示简短提示；普通缺陷不得通过“不支持”标签绕过验收。
- 本规格是实现工作的唯一聚合入口；更细的决策背景仍保留在 Wayfinder 路线图及其已解决票据中。
