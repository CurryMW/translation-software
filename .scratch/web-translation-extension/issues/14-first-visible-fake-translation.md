# 14 — 用 Fake 翻译一个可视文本内容块

**What to build:** 用户在获准的本地测试页面开启翻译后，可以看到一个当前可视文本内容块进入加载状态，并通过 Fake Translation Adapter 在原文下方得到固定译文，形成第一条贯穿 popup、content script、service worker、适配器和 React 页内 UI 的完整链路。

**Blocked by:** 13 — 按域名授权并记忆页面翻译开关

**Status:** ready-for-agent

- [ ] 定义并实现最小翻译服务适配器接缝，Fake Adapter 返回独立人工写定的确定性译文。
- [ ] content script 只提交当前视口中一个明确的静态文本内容块，并通过类型化消息取得统一翻译结果。
- [ ] 用户确认开始后200毫秒内在对应原文下方显示加载状态，原文保持不变。
- [ ] 成功译文使用 A「紧凑双语」呈现，默认展开，并显示轻量语言标签和收起/展开操作。
- [ ] 收起和重新展开仅改变 React UI，不再次调用 Fake Adapter。
- [ ] 页内译文由统一 React 渲染协调层管理，不为每个文本块创建互不协调的完整应用实例。
- [ ] 扩展样式限定在自身挂载范围内，基础浅色和深色夹具均不受全局样式污染。
- [ ] 重复触发扫描不会创建第二个译文容器。
- [ ] Playwright 从用户开启网站开始验证完整可见行为，而不是检查内部队列或 React 组件树。
