# 确定动态网页的增量翻译契约

Type: grilling
Status: resolved
Assignee: Curry学长（Codex 协作）
Blocked by: 02, 03

## Question

确定动态网页处理契约：如何发现滚动加载、异步更新和 SPA 路由产生的新文本内容块，如何生成稳定去重身份，扫描与翻译的节流/并发上限是多少，页面切换或卸载时如何取消任务，以及如何避免重复插入译文。

## Comments

首轮建议（历史记录，以下方最新用户反馈为准）：

1. 快速滚动时优先当前视口及附近内容；已滑远且尚未发出的任务退出队列，不追着整页翻译。滚回时仍可重新排队。
2. 展开长帖或原文更新时，移除过期译文，等待文字短暂停止变化后重译该块；连续输出的内容允许等稳定后再翻译，避免每增加几个字就产生一次请求。
3. 标签页转入后台时暂停新增自动请求，回到前台再继续；手动关闭翻译开关时清除队列及译文展示。已提交到供应商的请求不承诺可撤销计费。

工程落实草案（尚未实现；不要求用户选择技术参数）：

- 初次扫描后按页面变更做局部增量处理；跳过扩展自己插入的译文，避免循环触发。页面路由变化后重新建立当前页面范围。
- 区分展示身份和请求身份：前者沿用节点引用加规范化原文，后者还需包含供应商、源语言配置、目标语言及页面/文本版本，防止切换语言后误用旧结果。
- 每块最多保留一个译文容器；节点删除、重用、文本更新、页面导航或关闭开关后，旧版本返回值不能写回。可中止的本地请求尽力中止，但不声称服务端未处理。
- 扫描分片让出主线程；文字稳定等待和并发参数在实现时设置保守默认并测量，不把未测试数值当作性能保证；按最新用户要求不设置屏外预读范围。配额和重试策略由“确定翻译失败与调用成本控制策略”票据统一决定。
- 目标语言切换按已确认语言策略仅立即影响当前标签页，其他已打开标签页保持当前语言快照直到刷新，避免同页新旧内容语言混用。

### 最新用户反馈

- Q1 明确改为“只翻译可视区域的内容”：不预译视口附近或屏外内容；排队任务发出前重新检查可见性。此要求替代内容边界及语言切换决策中原先的“即将进入视口/到附近”范围。
- Q2 确认：展开长帖或原文变化后移除过期译文，等文字短暂停止变化再重译相应的可见内容块。
- Q3 要求：“切到其他标签页，若翻译插件开着的话就弹窗提示是否要翻译”。这替代原先“回到前台自动继续”的建议；尚不能推断全局开关、弹窗触发范围、频率或拒绝后的行为。

待确认的具体解释：切入的网站已开启翻译时，在新切入标签页内显示非阻塞确认浮层；确认前不发起新增翻译请求，选择“翻译”后开始，选择“暂不翻译”或关闭提示则本次停留不新增翻译，已有译文保留。网站未开启时不提示；每次重新切入均询问。这是建议，不是已批准行为。

以上为澄清过程记录，最终决定以下方 Answer 为准。

## Answer

用户明确确认可视区域限制、文字更新处理，并对切换标签页提示的具体解释回复“是的”。确定以下产品行为：

1. **仅翻译可视区域**：不预译屏外或视口附近内容。任务发出前重新检查可见性；已滑出视口且尚未发出的任务不提交，滚回后按需排队。
2. **仅更新变动内容**：展开长帖或原文变化时移除过期译文，等待文字短暂停止变化后重译相应的可见内容块，不随每几个新增字符反复请求。
3. **每次切入先询问**：每次切入一个已开启翻译的网站标签页，都在新切入标签页内提示“是否翻译”。确认之前不发起新增翻译请求；确认后才开始本次停留的增量翻译。
4. **拒绝不删除旧结果**：选择“暂不翻译”时，保留已有译文但不继续翻译。提示被关闭也不得视为同意。下一次重新切入仍询问；未开启翻译的网站不提示。
5. **后台不新增自动请求**：离开的标签页停止提交新增自动翻译任务；手动关闭网站开关则清除等待任务与译文展示，保留原文。已提交给供应商的请求不承诺能撤销处理或费用。

实现约束：采用局部增量扫描、稳定等待及有限并发，排除扩展自身内容；每个内容块至多一个译文容器。返回结果必须与当前页面、节点、原文版本及语言配置一致，过期响应不得写到更新后的内容上。具体性能参数及异常退避在实现、成本策略和验收阶段验证，不视为已测试的性能保证。

这是产品行为决策，尚未实现到正式扩展。页面内提示的视觉细节和键盘操作仍需实现与验证；A「紧凑双语」原型目前没有该提示。
