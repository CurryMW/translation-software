**What to build:** 用户在设置页输入自己的百度 APPID 与密钥后，可以由 service worker 通过百度通用文本翻译获得真实结果；在此之前，扩展必须证明凭据隔离、请求最小化、预算、错误处理和日志脱敏，并把真实烟囱测试限制为一次明确确认的小额固定请求。

**Blocked by:** 22 — 标签页切入确认并暂停后台调用; 23 — 支持开放 Shadow DOM 和获准 iframe

**Status:** passed

诊断跟进（2026-09-22）：用户多次尝试仍未通过，0.0.2 显示 `RUN_INTERNAL_FAILURE`。已在真实 production `dist` 的离线 Chromium 中，通过设置页双确认稳定复现相同错误：百度适配器默认将原生 `setTimeout`/`clearTimeout` 复制到普通对象，再作为对象方法调用，触发 `TypeError: Illegal invocation`；复现时 transport 调用次数为 0。0.0.3 改用箭头函数以 `globalThis` 调用原生计时器，同一用例恢复通过。此前“已增加用量即已发送”和“readiness 保存失败”的推断不成立：本地预算先于发送预留，无法据此确认百度实际用量。所有用户历史尝试的真实请求状态仍不能仅靠本地计数推断。

自动化补齐：真实 `dist` 测试从仅验证 prepare 延长到第二次确认后的完整流程，保留浏览器原生计时器，仅在外部 fetch 边界注入合成响应，另设离线模式；覆盖成功与 `54001` 鉴权失败、准备阶段零调用、确认后恰好一次调用、19 字符本地预算及服务端详情不回显。自动通过不代表真实账户烟囱通过。

人工验收（2026-09-24）：用户在 0.0.3 设置页完成真实百度人工烟囱；页面显示“人工烟囱已通过；重新确认当前标签页后，后续页面翻译将使用百度。”，并显示本地累计估算提交 133 个源字符。该累计值不是百度官方账单，也不用于推断请求次数；未记录凭据、响应正文或其他敏感数据。真实服务安全门通过。

- [x] 百度实现满足现有翻译服务适配器接口；Fake Adapter 仍是默认自动化实现，设置页不展示 DeepL 等未实现供应商。
- [x] 只有 service worker 可以读取 APPID 与密钥、计算签名和发起百度请求；content script、网页和 React UI 不获得敏感值。
- [x] 签名按 APPID、原文、随机 salt 和密钥生成32位小写 MD5，并使用独立固定向量验证；MD5 实现随扩展打包，不加载远程代码。
- [x] 请求使用 POST，只包含百度接口必需的 `q`、`from`、`to`、`appid`、`salt`、`sign`；密钥、签名原串、页面 URL、标题、账号和相邻上下文不发送。
- [x] 百度成功响应、语言映射和错误码转换为统一适配器结果，不向页面泄露原始鉴权材料或完整响应体。
- [x] 实际套餐、免费额度、QPS、语言方向和单次长度从用户当前账户重新核对；标准版按 QPS 1 串行。
- [x] 本地安全门覆盖凭据隔离、最小请求、字符预算、错误分类、超时/有限重试、日志脱敏、代次失效与并发撤销；只有显式人工成功后才切换普通页面任务到 Baidu。
- [x] 设置页烟囱测试只使用内置无敏感固定文本，总源字符不超过300，提交前显示字符数并二次确认，且不自动重试。
- [x] 真实凭据只由用户在已加载扩展设置页输入，不进入仓库、聊天、命令输出、快照或测试报告。
- [x] 自动 `verify` 即使运行环境存在真实凭据也不得访问百度；真实烟囱测试是独立人工操作。
