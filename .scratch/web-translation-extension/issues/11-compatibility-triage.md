# 制定 MVP 兼容性问题处置规则

Type: grilling
Status: resolved
Assignee: Curry学长（Codex 协作）
Blocked by: 09, 10

## Question

针对 MVP 实测中发现的站点差异，如何在“修复、通用降级、站点特例、明确延期”之间做决定？需要定义安全性、误翻译风险、页面破坏风险、复现稳定性和用户影响的判定门槛，并规定何时更新不支持列表或验收样本。

## Comments

### 第一轮：严重度与处置原则

❓ **Q1 - 不确定内容的默认行为**：无法确信某段文字是阅读内容而非按钮、账号信息或编辑内容时怎么办？

- A：先翻译，尽量提高覆盖率。
- B：跳过该内容块，不发送请求；如果整页都无法安全识别，则停止本页新增翻译并显示一条非阻塞提示。
- C：关闭所有网站的翻译功能。

➡️ 推荐 B。覆盖率和零误发不能同时绝对保证，隐私与页面安全优先；影响应限制在当前内容块或当前页面，而不是全局停用。

❓ **Q2 - 严重度分级**：采用哪套优先级？

- A：所有问题同等处理。
- B：阻断级（凭据/隐私、误发编辑内容、页面功能破坏、失控调用）；核心级（四个必测站核心路径或广泛通用场景失败）；兼容级（非核心网站稳定复现且可安全降级）；外观级（不影响阅读和操作的轻微样式问题）。
- C：按修复耗时排序。

➡️ 推荐 B。严重度由风险和用户影响决定，不由“是否容易修”决定；前两级阻断 MVP，后两级可按条件延期。

❓ **Q3 - 通用修复与站点特例**：什么时候允许为单个网站写适配逻辑？

- A：发现问题就先写站点选择器。
- B：先尝试能改善一类页面的通用修复；只有问题稳定复现、网站属于核心场景或影响显著、通用修复会伤害其他页面且存在可靠语义锚点时，才允许站点特例。
- C：永远禁止站点特例。

➡️ 推荐 B。站点选择器易随改版失效，但完全禁止会让 X 等核心动态站点无法落地；特例必须小、可关闭、可独立测试。

❓ **Q4 - 页面破坏时的回退**：如果插入译文导致布局错乱、按钮失效或滚动异常怎么办？

- A：保留译文并显示警告。
- B：立即移除本扩展在当前页插入的 UI，取消等待任务，暂停该页面会话并提示用户；保留网站长期设置，但下次切入仍需确认。
- C：卸载扩展。

➡️ 推荐 B。先恢复宿主页面，再保留可诊断状态；不能为了翻译继续影响原网站操作。

❓ **Q5 - 允许延期的必要条件**：一个兼容性问题何时可以延期？

- A：预计修复超过一天即可延期。
- B：必须同时满足：不涉及隐私/凭据/费用失控、不破坏页面、不影响四个必测站核心路径、非广泛通用缺陷、能安全跳过或降级、复现条件和用户影响已记录。
- C：个人使用，所有问题都可以延期。

➡️ 推荐 B。工期只影响排期，不会把高风险问题变成低风险问题。

❓ **Q6 - 不支持列表**：哪些问题可以正式写成“不支持”？

- A：任何暂时没修的问题。
- B：既定平台边界，或已经稳定复现、原因明确、满足延期条件且给出安全行为/替代办法的问题；普通缺陷仍保留为待修复，不得用“不支持”隐藏。
- C：不维护不支持列表。

➡️ 推荐 B。列表应描述真实能力边界，不是关闭缺陷的垃圾桶。

❓ **Q7 - 站点特例的生命周期**：特例代码需要什么约束？

- A：写进通用扫描器，后续不单独跟踪。
- B：放入独立适配器注册表，记录适用域名、触发条件、原因、夹具、回退行为和复查日期；失效时自动回到安全通用策略，不继续盲目匹配。
- C：直接复制一套扫描逻辑给每个网站。

➡️ 推荐 B。这样站点改版时能局部关闭或删除，不污染通用规则。

❓ **Q8 - 诊断与上报**：个人 MVP 如何收集兼容性证据？

- A：自动上传页面信息和正文。
- B：不做任何遥测；仅在当前页面会话保存脱敏计数和错误类别，人工记录网站类型、Chrome/扩展版本、复现步骤、期望/实际、风险等级和处置结论，不保存正文、账号或完整 URL。
- C：永久保存完整调试日志。

➡️ 推荐 B。兼容性证据必须足够复现，但不能反过来制造新的浏览历史或内容隐私问题。

### 第二轮：落地判定与回归范围

❓ **Q9 - 固定判定顺序**：发现兼容性问题后按什么顺序选择动作？

- A：先估算哪个方案开发最快。
- B：依次判断安全阻断、是否属于通用规则缺陷、是否需要重要站点特例、能否安全降级延期；没有满足延期条件的问题保持阻断。
- C：默认先延期，使用频繁后再修。

➡️ 推荐 B。固定顺序为：隔离风险 → 通用修复 → 必要站点特例 → 安全延期，避免用低成本方案掩盖高风险问题。

❓ **Q10 - 回归资产新增规则**：发现真实站点缺陷后是否补自动化资产？

- A：真实站点人工复测即可。
- B：能抽象为通用行为的缺陷必须增加最小本地夹具和失败测试；站点特例必须增加不复制真实正文的合成结构夹具；纯外部服务中断只保留脱敏人工记录。
- C：直接保存出问题页面的完整 HTML。

➡️ 推荐 B。每次修复都留下能独立复现的资产，同时不持久化第三方页面或用户内容。

❓ **Q11 - 已知不安全网站的保护**：某域名稳定触发页面破坏或误发风险、但尚未修复时怎么办？

- A：仍允许自动翻译，只显示警告。
- B：将该域名加入本地兼容性暂停表，阻止新增请求并明确提示“当前版本已暂停此网站”；修复并通过回归后移除。用户不能绕过隐私/页面破坏类暂停。
- C：完全卸载扩展。

➡️ 推荐 B。会话级回退处理偶发故障；已确认的稳定高风险问题则需要跨会话保护，否则用户每次进入都会重复踩坑。

❓ **Q12 - 修复后的回归范围**：不同类型修复要重测什么？

- A：只重测出问题的网站。
- B：通用扫描/状态修复运行完整 `verify` 加四站人工核心检查；站点特例运行完整 `verify`、目标站和至少一个无关站；隐私/费用修复另加完整安全门；纯外观修复运行相关 UI/截图和目标页检查。
- C：所有修复都重跑所有人工项目。

➡️ 推荐 B。风险扩散范围不同，回归范围也应不同；通用修复影响最大，必须覆盖最广。

❓ **Q13 - 问题关闭条件**：何时允许标记兼容性问题已解决？

- A：代码已经修改。
- B：修复前有稳定复现或证据，修复后对应自动/人工检查通过，没有引入更高严重度回归；若是站点特例，还必须验证失效时能安全跳过或回退。
- C：一次刷新后看起来正常。

➡️ 推荐 B。没有前后证据就无法区分真正修复、偶然恢复或网站临时变化。

❓ **Q14 - 已知限制的呈现位置**：用户在哪里看到延期和不支持边界？

- A：只写在开发票据里。
- B：在随扩展交付的 `KNOWN_LIMITATIONS.md` 维护完整清单；扩展只在检测到相关场景时显示简短、可执行提示，不向普通页面长期展示开发术语。
- C：每次打开 popup 都显示全部限制。

➡️ 推荐 B。开发记录负责完整性，运行时提示负责当前用户动作，避免把设置界面变成问题列表。

❓ **Q15 - 复查时机**：延期问题和站点特例什么时候重新验证？

- A：用户再次遇到才检查。
- B：每个 MVP 候选版本复查；Chrome 主版本升级、目标站明显改版、通用扫描器变更或适配器测试失败时立即复查相关项。
- C：固定每年检查一次。

➡️ 推荐 B。兼容性依赖浏览器和站点结构，按变化触发比单纯按日历更有效。

## Answer

MVP 使用固定、风险优先的兼容性处置顺序：先隔离隐私、页面破坏与费用风险，再判断是否需要通用修复；只有重要场景无法由通用规则安全解决时才建立独立站点特例；满足全部安全条件的问题才允许明确延期。修复成本只影响排期，不降低问题严重度。

### 严重度与发布影响

1. **阻断级**：凭据或正文泄露、误发编辑/交互内容、宿主页面按钮/滚动/布局等核心功能被破坏、请求或费用失控。立即停止受影响页面新增请求并回退扩展 UI；解决或建立不可绕过的安全隔离前不得交付。
2. **核心级**：X、Wikipedia、GitHub、Hacker News 任一必测站核心路径失败，或缺陷影响多个结构无关的网站/可由通用夹具复现。必须优先通用修复并阻断 MVP。
3. **兼容级**：只影响非核心网站、稳定复现、不是通用缺陷，且能够在不误发、不破坏页面、不造成费用风险的前提下跳过或降级。记录完整后可明确延期。
4. **外观级**：轻微间距、颜色或排版差异，不影响阅读、操作、可访问性和内容对应关系。可以延期，但必须记录并在相关 UI 变化时复查。

### 固定决策流程

1. 记录脱敏环境、复现步骤、期望/实际和影响范围，不保存正文、账号、密钥、完整 URL 或真实页面截图。
2. 如果存在阻断级风险，当前内容块不发送；页面级风险则移除本扩展 UI、取消等待任务并暂停当前页面会话。
3. 若问题能在通用夹具复现，或出现在多个结构无关的网站，按通用缺陷修复；不得用网站选择器掩盖通用算法问题。
4. 通用修复会伤害其他网站、问题稳定复现且网站属于核心场景或影响显著，并存在可靠语义锚点时，才允许站点特例。
5. 不满足通用修复或站点特例条件时，只有同时满足全部延期条件才能延期；否则保持阻断状态。

### 安全降级与兼容性暂停

- 无法确认某个内容块是否为安全阅读内容时直接跳过，不发送请求。
- 整页无法安全识别时暂停本页新增翻译并显示一条非阻塞、可执行提示，不影响其他标签页或网站。
- 页面破坏时先恢复宿主页面：移除扩展插入 UI、取消排队任务并暂停当前页面会话；长期网站设置保留，下次切入仍需确认。
- 某域名已被稳定确认会触发隐私、页面破坏或费用风险但尚未修复时，加入本地兼容性暂停表，跨会话阻止新增请求并提示“当前版本已暂停此网站”。用户不得绕过高风险暂停；修复并通过回归后移除。

### 站点特例规则

站点特例放入独立适配器注册表，不复制完整扫描器。每项记录适用域名、可靠触发条件、引入原因、合成夹具、安全回退、负责人状态和复查日期。适配器失效时，只有通用安全检查独立通过才回到通用策略，否则跳过并暂停受影响范围，不盲目继续匹配。

### 回归资产与范围

- 通用缺陷必须新增最小本地夹具和行为接缝上的失败测试；站点特例必须新增不复制真实正文的合成结构夹具；纯外部服务中断只保留脱敏人工记录。
- 通用扫描或状态修复：运行完整 `verify`，并人工检查四个必测站核心路径。
- 站点特例：运行完整 `verify`，人工检查目标站和至少一个结构无关的网站。
- 隐私或费用修复：除对应回归外，重跑完整真实服务安全门。
- 纯外观修复：运行相关 React 行为、局部截图回归及目标页面人工检查。

测试失败默认不通过重复运行来掩盖。先分类为代码回归、测试缺陷或外部站点变化；核心本地测试不得跳过或隔离后放行。

### 关闭、延期与复查

- 问题关闭必须具备修复前复现证据、修复后对应自动/人工检查结果，并确认没有引入更高严重度回归；站点特例还必须验证失效时能够安全跳过或回退。
- 明确延期必须同时满足：不涉及隐私/凭据/费用失控、不破坏页面、不影响四个必测站、不是广泛通用缺陷、存在安全跳过或降级行为，并记录复现条件、用户影响和替代办法。
- `KNOWN_LIMITATIONS.md` 保存完整的不支持和延期清单。扩展只在检测到相关场景时显示简短提示，不在普通 popup 中长期堆放开发术语。
- 每个 MVP 候选版本复查延期项和站点特例；Chrome 主版本升级、目标站明显改版、通用扫描器变化或适配器测试失败时立即复查相关项。

不支持列表只容纳既定平台边界，或原因明确、稳定复现、满足延期条件且有安全行为的问题。普通缺陷继续作为待修复事项，不能通过标记“不支持”绕开放行门槛。
