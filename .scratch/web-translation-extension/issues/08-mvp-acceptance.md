# 定义跨网站 MVP 验收标准

Type: grilling
Status: resolved
Assignee: Curry学长（Codex 协作）
Blocked by: 02, 03, 04, 05, 06, 07

## Question

定义 MVP 验收标准：首批必须验证的网站类型与样本页面、Chrome 最低版本、可接受的首译延迟和滚动增量延迟、翻译正确率/可读性检查方法、性能预算、权限与隐私检查清单，以及哪些兼容性问题可以明确延期。

## Comments

### 第一轮：验收口径

❓ **Q1 - 测试样本**：首发验收使用哪组网页？

- A：只测 X 和一个普通文章页，成本最低但难以证明通用性。
- B：一套可控的本地夹具，加 X 信息流、英文 Wikipedia 文章、GitHub Issue/Discussion、Hacker News 评论页四类真实页面。
- C：只测本地夹具，可重复但不能暴露真实网站兼容问题。

➡️ 推荐 B。本地夹具覆盖加载、追加、更新、滚动、Shadow DOM 与 iframe 边界；四个真实样本分别覆盖虚拟信息流、长文章、代码混排和嵌套评论。

❓ **Q2 - Chrome 范围**：最低支持版本如何定？

- A：仅保证开发时电脑上的当前 Chrome。
- B：声明 Chrome 120 及以上，并在当前稳定版人工验收。
- C：持续覆盖多个旧版本。

➡️ 推荐 B。个人 MVP 没必要承担大规模旧版本兼容成本，但仍给出明确下限；若实现依赖更高版本 API，必须提高声明版本而不是静默失效。

❓ **Q3 - 响应时间**：怎样区分扩展性能和百度网络延迟？

- A：只记录从点击到译文出现的总时间。
- B：分别验收本地反馈、扩展处理开销和端到端译文时间。
- C：不设数字，只凭主观感受。

➡️ 推荐 B：确认后 200 ms 内出现加载状态；单次可视区域扫描的 P95 不超过 100 ms；正常网络下首批首条译文中位数不超过 2.5 秒、P95 不超过 6 秒。外部服务超时不直接算扩展性能失败，但必须进入可理解的等待或失败状态。

❓ **Q4 - 翻译质量**：怎样避免把第三方译文问题和扩展集成问题混为一谈？

- A：只看中文读起来是否自然。
- B：集成完整性与语义可读性分开验收。
- C：只要 API 返回成功就算通过。

➡️ 推荐 B：30 个跨类型人工样本中，内容对应、顺序、目标语言、无遗漏/重复/截断等集成完整性必须 100%；至少 90% 能正确理解主旨且无反向含义。明确属于百度的措辞质量问题单独记录，不判定为扩展数据损坏。

❓ **Q5 - 运行性能**：个人 MVP 的浏览体验门槛是什么？

- A：只要不崩溃即可。
- B：设保守预算并做持续滚动测试。
- C：做接近商店级的多设备性能基准。

➡️ 推荐 B：并发数随百度套餐限制；10 分钟连续滚动不得出现明显卡顿、重复译文或失控请求；停止滚动且页面无变化时不得继续扫描或请求；扩展带来的内存增量目标不超过 50 MB，超出需定位或记录理由。

❓ **Q6 - 隐私放行**：隐私检查应当是建议项还是阻断项？

- A：全部作为发布阻断项。
- B：只检查凭据不显示在页面上。
- C：MVP 暂不检查。

➡️ 推荐 A：安装时无全站权限、按域名授权、凭据存储限制为可信扩展上下文、content script 和页面不可读凭据、网络请求只含当前文本块及百度接口必需的鉴权元数据（不含密钥本身和签名原串）、日志无正文/完整网址/密钥、清除数据有效；任一不通过均不得标记 MVP 完成。

❓ **Q7 - 允许延期的兼容性**：哪些问题可以不阻塞 MVP？

- A：只有已明确列为不支持的技术边界，以及非必测网站的特殊 DOM 适配问题可以延期。
- B：X 失败也可延期，只要静态文章可用。
- C：任何单站问题都阻塞发布。

➡️ 推荐 A：closed Shadow DOM、canvas/图片文字、浏览器 PDF、Chrome 内部页、无权限的跨域 iframe 明确不支持；非必测网站只有在安全降级、不误发内容、不破坏页面并记录复现条件时才可延期。X 等四类必测样本的核心路径失败必须修复。

## Answer

用户确认全部采用推荐方案，MVP 放行门槛如下：

1. **样本与范围**：使用可控本地测试夹具，加 X 信息流、英文 Wikipedia 文章、GitHub Issue/Discussion、Hacker News 评论页四类真实样本；`minimum_chrome_version` 以 120 作为经 API 可用性核对的设计兼容下限，并在当前稳定版实际验收。未取得 Chrome 120 环境运行前，不声称所有 Chrome 120+ 版本均已实测覆盖。
2. **时延与性能**：确认后 200ms 内显示加载状态；单次可视区域扫描 P95 不超过 100ms；正常网络下首条译文中位数不超过 2.5 秒、P95 不超过 6 秒。连续滚动 10 分钟不得出现明显卡顿、重复译文或失控请求；页面静止后不得继续扫描或请求；扩展内存增量目标不超过 50MB。
3. **质量**：对 30 个跨类型人工样本，内容对应、顺序、目标语言、无遗漏/重复/截断等集成完整性必须 100%；至少 90% 能正确理解主旨且无反向含义。第三方措辞质量问题与扩展数据损坏分开记录。
4. **隐私**：安装时无全站权限，按域名授权；凭据只在可信扩展上下文可读；页面和 content script 不可读凭据；请求只含当前文本块及百度接口必需的 `q`、`from`、`to`、`appid`、`salt`、`sign`，不含密钥本身或签名原串；日志不含正文、完整网址或密钥；清除数据有效。任一项失败都阻断 MVP。
5. **延期边界**：closed Shadow DOM、canvas/图片文字、浏览器 PDF、Chrome 内部页、无权限的跨域 iframe 明确不支持。非必测网站的特殊 DOM 适配仅在安全降级、不误发内容、不破坏页面且记录复现条件时延期；X 等核心样本失败不得延期。

这些指标是个人 MVP 的放行门槛，不是对所有网站、所有网络条件或百度翻译质量的绝对保证。
