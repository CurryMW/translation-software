# 在个人 Chrome MVP 中选择百度首发翻译接口

Type: research
Status: resolved

## Question

用户已决定把首发服务从 DeepL 改为百度翻译。百度通用文本翻译与百度大模型文本翻译中，个人使用的 Chrome MVP 应首发哪一个？比较官方资料中的鉴权字段、开通/认证要求、价格与免费额度、QPS、单次文本限制、语言覆盖与自动检测、错误语义、数据与凭据风险、service worker 接入复杂度；给出明确首选、备用及实现前需实测/复核的事项。

## Previous answer — superseded

首发选择 DeepL API，备用选择 Microsoft Translator；内部通过统一翻译服务适配器隔离供应商。请求由 Manifest V3 service worker 代理，内容脚本不得接触 API Key。个人版可以把用户自己的 Key 存入 `chrome.storage.local`，但必须明确这不构成真正的密钥保护；开发者 Key 不得打包进扩展，若未来公开发布则改用自有后端或严格的 BYOK 模式。

价格、免费额度、速率限制、数据政策和语言覆盖会变化，实施前需重新核验，并用 50–100 个真实网页文本块测量翻译质量与 P50/P95 延迟。

研究记录：[Chrome 网页翻译扩展：首发翻译服务研究](../../../research/translation-provider-comparison.md)

2026-09-07：用户明确决定首发服务改为百度翻译，以上 DeepL 结论失效。本票据重新打开，等待百度两种文本接口的研究答案；地图在新答案产生前不列出服务选型结论。

## Answer

首发改为百度通用文本翻译 API：个人认证条件允许时使用高级版；尚未认证时可用标准版验证，但必须按官方 QPS 1 串行处理，不能据此承诺性能。百度大模型文本翻译保留为后续质量对照，待价格、配额、账户 QPS、数据条款和真实样本实测后再决定是否替换默认接口。

正式适配器使用 `APPID + 密钥 + MD5 签名`，请求由 Manifest V3 service worker 发送，内容脚本不得读取凭据；通过统一适配器隔离百度的鉴权、语言代码和错误码。浏览器内保存凭据仍不安全，未来公开版本需要后端代理。

研究记录：[百度首发翻译接口研究](../../../research/baidu-translation-interface.md)。价格、套餐、配额、语言方向和数据条款属于动态事实，实施前必须在目标账户中复核，并用 50–100 个真实网页文本块测试质量与 P50/P95 延迟。
