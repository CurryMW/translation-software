# 百度首发翻译接口研究

## 研究问题

用户已决定 Chrome 网页翻译 MVP 首发使用百度翻译。需要在百度通用文本翻译与百度大模型文本翻译之间选择首发接口，并明确浏览器扩展接入约束。

## 结论

首发建议使用 **百度通用文本翻译 API**；具备个人认证条件时优先高级版，否则先用标准版验证流程。**百度大模型文本翻译 API** 保留为后续质量对照，不作为首发默认。

理由不是“大模型一定不好”，而是 MVP 当前更需要可预测的开通条件、免费额度、QPS、超额单价和错误语义。通用接口的这些运营边界在官方页面上相对明确；大模型接口文档明确了能力与鉴权，但本次未在无需登录的官方页面中核实完整价格、免费额度和账户级 QPS。缺少这些事实时直接选大模型版，会把成本和并发风险带进自动翻译流程。

## 官方事实对比

### 百度通用文本翻译

- HTTPS 端点：`https://fanyi-api.baidu.com/api/trans/vip/translate`。
- 鉴权：`APPID + q + salt + 密钥` 拼接后生成 32 位小写 MD5 签名；请求可使用 GET 或 POST，MVP 应使用 POST，避免把正文放入 URL。
- 自动检测：`from=auto`；目标语言不能为 `auto`。
- 官方接入说明显示：标准版无需认证可开通；高级版需个人认证。标准版每月 5 万免费字符、QPS 1、单次最长 1000 字符；高级版每月 100 万免费字符、QPS 10、单次最长 6000 字符；两者公开页列出的超额价格为 49 元/百万字符。
- 官方产品页称接口能力覆盖 200+ 语种，但开通页对标准版/高级版权益显示 28 个常见语种。实施时应以实际账户套餐和语言方向列表验证，不能直接把“200+”当作个人套餐承诺。
- 响应具有 `error_code` / `error_msg`；官方文档列出签名错误、访问频率受限、余额不足、语言方向不支持、服务关闭、IP 封禁等错误。

来源：[通用文本翻译接入文档](https://fanyi-api.baidu.com/product/113)、[接入服务与套餐](https://fanyi-api.baidu.com/doc/13)、[通用文本翻译开通页](https://fanyi-api.baidu.com/access/0/1)、[产品介绍](https://fanyi-api.baidu.com/product/11)。

### 百度大模型文本翻译

- HTTPS 端点：`https://fanyi-api.baidu.com/ait/api/aiTextTranslate`。
- 推荐鉴权：`Authorization: Bearer <API_KEY>`，同时请求体包含 `appid`；也兼容通用接口的签名方式。
- 可选 `model_type=llm` 或 `nmt`，并支持翻译指令、术语与标签处理等能力；MVP 的逐块网页翻译暂不需要这些增强项。
- 自动检测：`from=auto`；目标语言不能为 `auto`。
- 官方文档建议单次内容控制在 2000 字符内，上限 6000 字符，并列出 QPS 超限、鉴权、模型参数、文本过长和语言方向等错误码。
- 官方接入文档要求完成认证并开通服务。本次没有从无需登录的官方页面核实完整的当前价格、免费额度、账户级 QPS及数据保留条款，这些必须在使用控制台和协议页再次确认。

来源：[大模型文本翻译 API 接入文档](https://fanyi-api.baidu.com/doc/21)、[百度 API Key 管理](https://fanyi-api.baidu.com/manage/apiKey)。

## Chrome 扩展约束

- 两种接口都应由 Manifest V3 service worker 发起请求，供应商域名使用最小化主机权限；网页内容脚本只发送文本任务，不接触凭据。
- 通用接口的 MD5 签名增加一项实现工作。浏览器原生 Web Crypto 不提供 MD5，若使用第三方实现必须把经过审查的代码随扩展打包，不能运行时加载远程脚本。
- 大模型接口的 Bearer 鉴权更简单，但简单不等于安全。百度官方明确提示不要在浏览器或客户端代码中暴露 API Key。
- 个人、解压加载的 MVP 可以让用户自行输入凭据并保存在本机，但必须明示不构成安全保险箱；公开发布版本需要后端代理，不能把开发者凭据打包进扩展。

来源：[Chrome 跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[Chrome 权限声明](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)、[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)、[百度 API Key 管理](https://fanyi-api.baidu.com/manage/apiKey)。

## 对 MVP 的明确选择

1. 默认适配器：百度通用文本翻译。
2. 凭据字段：`APPID` 与密钥；仅 service worker 可读取。
3. 计划选择：个人认证可接受时使用高级版；若尚未认证，标准版可以启动验证，但必须按 QPS 1 严格串行排队，因此不应把其速度作为 MVP 性能目标。
4. 大模型接口：作为后续适配器与翻译质量对照，只有在价格、配额、QPS、数据条款和真实网页样本验证后才考虑替换默认接口。
5. 适配器返回统一错误类别，保留百度原始错误码用于不含正文的诊断，不把百度签名和语言代码泄漏到内容扫描层。

## 实现前必须复核与实测

- 登录目标百度账号后确认实际套餐、认证状态、当前免费额度、超额价格、QPS 和可用语言方向；运营数据可能变化。
- 查阅签约时展示的数据处理与隐私条款。本次公开 API 接入文档不足以证明文本不保留或不用于模型改进。
- 使用同一组 50–100 个真实网页文本块，对通用标准/高级版与大模型版测试译文质量、P50/P95 延迟、长文本、自动检测和混合语言表现。
- 验证签名实现与百度示例一致，并确保日志、异常和调试工具不会输出密钥、签名原串或正文。
- 验证标准版 QPS 1 对“只翻译可视区域”的实际体验是否可接受；不可接受时升级高级版或调整产品并发预期。
